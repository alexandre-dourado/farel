📺 O Client "Burro": React + Tailwind

A nossa interface foi projetada para ser completamente stateless (sem estado complexo local). Ela tem apenas duas responsabilidades:

  1. Renderizar o Estado: Pega o JSON mais recente do servidor e atualiza a tela usando Tailwind CSS para uma estilização rápida e responsiva.
  2. Enviar Ações: Quando o jogador interage (ex: comprar uma empresa), o cliente envia a requisição (POST) e espera a validação do servidor.

🔄 Multiplayer via Polling

Para manter todos os jogadores sincronizados sem a complexidade (e custo) de WebSockets, adotamos uma estratégia de Short Polling. A cada 3 segundos, o cliente React pergunta ao servidor: "Tem alguma novidade?".

Exemplo do Hook React (Polling):

useEffect(() => {
  const pollState = async () => {
    try {
      const res = await fetch(SCRIPT_URL);
      const data = await res.json();
      setGameState(data);
    } catch (error) {
      console.error("Erro no polling:", error);
    }
  };

  // Executa a cada 3 segundos
  const intervalId = setInterval(pollState, 3000);
  
  // Limpa o intervalo ao desmontar
  return () => clearInterval(intervalId);
}, []);

�� Backend Relay: Google Apps Script (GAS)

No coração da nossa persistência, usamos o Google Sheets como um "banco de dados" e o Google Apps Script (Code.gs) como nossa API Relay. O script processa doGet para retornar o estado atual e doPost para processar as ações dos jogadores de forma atômica.

Exemplo do endpoint POST em Code.gs:

function doPost(e) {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();
  
  // 1. Faz parse da ação do jogador
  const action = JSON.parse(e.postData.contents);
  
  // 2. Processa a lógica do jogo (Validação e Mutação)
  const currentState = JSON.parse(sheet.getRange('A1').getValue() || "{}");
  const newState = GameEngine.processAction(currentState, action);
  
  // 3. Salva o novo estado na célula
  sheet.getRange('A1').setValue(JSON.stringify(newState));
  
  // 4. Retorna confirmação para o cliente
  return ContentService.createTextOutput(JSON.stringify({ success: true }))
    .setMimeType(ContentService.MimeType.JSON);
}

Resumo do Arquiteto: Esta arquitetura Serverless (GAS) + Stateless UI (React) + Polling permite iterar rapidamente na lógica do jogo ("Game Engine") sem se preocupar com infraestrutura pesada de servidores ou bancos de dados relacionais. Perfeito para um MVP ágil!

Part 3: Core Game Engine (TypeScript)

Bem-vindo ao coração do Farel Virtual MVP! Aqui nós abandonamos os side-effects e abraçamos o funcional. A máquina de estados do nosso engine, localizada em game/engine, é completamente isolada. Isso significa zero acoplamento com a UI. O motor processa ações e retorna um estado novo, fresco e clonado.

Imutabilidade Profunda

Nós levamos a imutabilidade a sério. Cada transição de estado utiliza a API nativa structuredClone para garantir que o estado anterior não seja modificado. Isso previne bugs assombrosos e facilita a implementação de features como "desfazer" ou replays. 

export function applyAction(state: GameState, action: GameAction): GameState {
  // O sagrado clone profundo
  const nextState = structuredClone(state);

  switch (action.type) {
    case 'PLAY_CARD':
      return playCard(nextState, action.payload);
    case 'RESOLVE_ATTACK':
      return resolveAttack(nextState, action.payload);
    // ...
    default:
      return nextState;
  }
}

Fases e Transições

O loop principal é dividido em fases bem definidas. Quando chamamos startTurn, o engine reseta o mana, compra uma carta e lida com condições de manutenção. O fluxo de playCard e resolveAttack verifica todas as regras de validação (recursos suficientes, alvos válidos) antes de mutar o clone e retorná-lo.

Edge-Cases: Summoning Sickness & 1d6 Damage

Regras de negócio complexas? Temos! Criaturas recém-invocadas sofrem de Summoning Sickness (enjoo de invocação) — uma flag que é limpa na próxima fase de startTurn do controlador.

E quanto ao dano, nós temos mecânicas baseadas em rolagem de dados (1d6). O motor permite injetar uma seed ou um resolvedor RNG customizado, mantendo a engine determinística para os testes unitários, mas caótica e divertida durante o gameplay real. Dano ilimitado?
